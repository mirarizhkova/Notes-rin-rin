# Notes RinRin: Cloud.ru (подготовка к развёртыванию)

## Что уже реализовано

- Существующий локальный режим (IndexedDB) продолжает работать на GitHub Pages.
- При запуске в Cloud.ru Container Apps сайт обслуживает Node.js-сервер из `server.mjs`.
- API на том же домене хранит резервную копию библиотеки в закрытом бакете **Cloud.ru Evolution Object Storage** через S3.
- В библиотеке появляется кнопка **☁ Синхронизировать**, если сервер настроен.
- Синхронизация пока **ручная**: загружаются обе библиотеки, записи объединяются по ID, затем общая копия сохраняется в облако и локально.
- В облаке хранится один объект `backups/library-v1.json`, включающий PDF, блокноты и штрихи. Содержимое PDF кодируется в base64.
- Удаления не синхронизируются. При одновременном редактировании одной страницы на двух устройствах выбирается более поздняя запись страницы, и часть штрихов может быть потеряна. Для начального релиза не редактируй одну страницу параллельно.
- Ограничение копии: **100 МиБ вместе с base64**. Для больших PDF потребуется отдельная загрузка файлов, которую пока не реализовали.

## Шаг 1. Object Storage

1. В Cloud.ru Evolution создай приватный бакет, например `notes-rinrin-storage`.
2. Включи **версионирование** бакета. При новой синхронизации предыдущая версия объекта останется доступна для восстановления (учти стоимость хранения версий).
3. Создай сервисный S3-ключ с минимальными необходимыми правами чтения/записи объектов этого бакета. Не добавляй ключи в репозиторий, HTML или JavaScript.

Документация:

- https://cloud.ru/docs/s3e/ug/topics/guides__bucket-create
- https://cloud.ru/docs/s3e/ug/topics/guides__versioning__manage-versioning
- https://cloud.ru/docs/s3e/ug/topics/concepts__storage-access-styles

## Шаг 2. Container Apps

В этой ветке уже есть `Dockerfile`. Можно собрать Docker-образ и запустить его в Evolution Container Apps, в том числе через Workflow Studio. Приложение слушает `0.0.0.0` и порт из переменной `PORT` (по умолчанию 8080).

Официальная инструкция по деплою из Git-репозитория:
https://cloud.ru/docs/tutorials-evolution/list/topics/container-apps__deploy-app-with-workflow

Задай **переменные окружения во время запуска контейнера**, а секреты добавь через Cloud.ru Secret Management:

| Переменная | Значение |
| --- | --- |
| `S3_BUCKET` | `notes-rinrin-storage` или имя твоего бакета |
| `S3_ACCESS_KEY_ID` | S3 ID в формате `tenant_id:key_id` |
| `S3_SECRET_ACCESS_KEY` | Секретная часть S3-ключа |
| `S3_ENDPOINT` | `https://s3.cloud.ru` (значение по умолчанию) |
| `S3_REGION` | `ru-central-1` (значение по умолчанию) |
| `NOTES_PASSWORD` | Отдельный длинный пароль для входа в библиотеку |
| `SESSION_SECRET` | Случайная секретная строка длиной не менее 32 символов |
| `PORT` | `8080`, если не выставляется самой платформой |

Документация про секреты:
https://cloud.ru/docs/container-apps-evolution/ug/topics/concepts__runtime

Если какая-либо обязательная переменная отсутствует, сайт запускается в локальном режиме: API показывает `configured: false` и кнопка облака скрывается.

## Шаг 3. Первое использование

1. Открой новый HTTPS-адрес Container Apps. Убедись, что сайт доступен.
2. На устройстве со старой библиотекой открой **GitHub Pages** и нажми **Экспорт**, чтобы сохранить локальную копию на всякий случай.
3. На новом Cloud.ru-адресе нажми **Импорт** и выбери сохранённую копию.
4. Нажми **☁ Синхронизировать**, введи пароль `NOTES_PASSWORD`. Копия появится в закрытом бакете.
5. На другом устройстве открой новый адрес и снова нажми **☁ Синхронизировать**. Документы и штрихи загрузятся туда.

Важно: браузеры считают адреса GitHub Pages и Cloud.ru разными сайтами. IndexedDB между ними не переносится автоматически; используй экспорт/импорт.

## Безопасность

- S3-ключи используются только на сервере; клиент видит лишь API на собственном домене.
- Сессия браузера: подписанная cookie с `HttpOnly`, `Secure` на production и `SameSite=Strict`.
- Запросы записи проверяют `Origin`; вход ограничен числом попыток.
- API и файлы в бакете закрыты авторизацией, публичный доступ бакету включать не нужно.
- Сайт на Cloud.ru может быть публично доступен до ввода пароля, но данные библиотеки доступны после входа.
- Во время первой настройки сначала используй тестовый PDF, а затем переноси основную библиотеку.
